# shardkeep

shardkeep упаковывает большие папки с данными в сжатые части (архивы tar со сжатием zstd), проверяет архивы по манифестам, загружает их в Hugging Face или облачное хранилище и восстанавливает данные. Инструмент рассчитан на сотни гигабайт и сотни тысяч файлов: датасеты, результаты экспериментов, веса моделей.

- **Части примерно одинакового размера** (по умолчанию 4 ГБ исходных данных). Такие файлы удобно загружать: Hugging Face допускает не более 10 000 файлов в одной папке, а облачные клиенты передают мелкие файлы очень медленно.
- **Манифест каждой части**: путь, размер, время изменения и SHA-256 каждого файла. По манифестам проверяется, что архивы целы и совпадают с исходной папкой.
- **Уровень сжатия по содержимому.** Текст, JSON и CSV сжимаются высоким уровнем, а фото, видео и архивы, которые уже сжаты, собираются в отдельные части и сжимаются быстро.
- **Продолжение после прерывания** упаковки и загрузки.
- **Одна команда перед удалением исходных данных**: проверка архивов, исходных папок и загрузки.
- **Восстановление без shardkeep**: рядом с архивами кладется отдельный скрипт `pack_shards.py`, которому нужны только Python 3.8+ и пакет zstandard. Каждая часть распаковывается и стандартными программами `zstd` и `tar`.

Сообщения программы выводятся на английском.

## Установка

Нужен Python 3.10 или новее. Пакет лучше ставить в отдельную виртуальную среду: huggingface_hub 2.x конфликтует с некоторыми пакетами (например, tokenizers требует версию ниже 2.0).

Windows (PowerShell):

```powershell
python -m venv $HOME\shardkeep-venv
```

```powershell
& $HOME\shardkeep-venv\Scripts\Activate.ps1
```

```powershell
pip install "shardkeep[hf] @ git+https://github.com/Expl0iD-Dev-Team/shardkeep"
```

Linux и macOS:

```bash
python3 -m venv ~/shardkeep-venv && . ~/shardkeep-venv/bin/activate
pip install "shardkeep[hf] @ git+https://github.com/Expl0iD-Dev-Team/shardkeep"
```

Без `[hf]` ставится только упаковка, проверка и распаковка. Для загрузки через rclone нужна [программа rclone](https://rclone.org/install/), для JPEG XL нужны программы `cjxl` и `djxl` из [libjxl](https://github.com/libjxl/libjxl/releases).

## Команды

| Команда | Что делает |
|---|---|
| `shardkeep analyze ПАПКА` | разбирает папку: объем по папкам и категориям файлов, дубликаты, состояние git-репозиториев, оценка сжатия, рекомендации. Только чтение |
| `shardkeep pack ПАПКА АРХИВЫ` | упаковывает папку в набор частей |
| `shardkeep verify АРХИВЫ` | проверяет архивы по манифестам; с `--src` также проверяет, что исходная папка упакована полностью и не менялась |
| `shardkeep unpack АРХИВЫ КУДА` | распаковывает все наборы, один набор (`--name`) или файлы по шаблону (`--pattern`) |
| `shardkeep upload АРХИВЫ --hf USER/DATASET` | загружает в датасет Hugging Face (по умолчанию приватный) или через rclone (`--rclone yadisk:backup`) |
| `shardkeep check-upload АРХИВЫ --hf USER/DATASET` | сверяет загруженные файлы с локальными по размеру и SHA-256, ничего не скачивая |
| `shardkeep check АРХИВЫ --hf USER/DATASET` | все проверки перед удалением исходных данных и итоговый вывод |
| `shardkeep card АРХИВЫ` | создает или обновляет карточку датасета `README.md` |
| `shardkeep compare-zip АРХИВ.zip ПАПКА` | проверяет, повторяет ли zip-архив распакованную папку |

Подробная справка: `shardkeep <команда> --help`.

## Сценарии

Во всех примерах `D:\work\project` – рабочая папка, `E:\backup\dataset` – папка для архивов на другом диске. Команды для Windows приведены по одной: многострочные команды при вставке в PowerShell иногда склеиваются в одну строку.

### Освободить диск

1. Разобрать рабочую папку и посмотреть, что занимает место:

   ```powershell
   shardkeep analyze "D:\work\project" --out "D:\project_report"
   ```

   В `D:\project_report\report.md` будут объемы по папкам и категориям, дубликаты, git-репозитории с незафиксированными изменениями и оценка сжатия. Окружения и кэш можно удалить сразу, код должен быть в git.

2. Упаковать папки с данными (каждая папка становится набором):

   ```powershell
   shardkeep pack "D:\work\project\data" "E:\backup\dataset"
   ```

   ```powershell
   shardkeep pack "D:\work\project\results" "E:\backup\dataset"
   ```

3. Загрузить и проверить перед удалением (см. следующий сценарий). Удалять исходные папки можно только после итога `SAFE TO DELETE`.

### Резервная копия датасета на Hugging Face

1. Войти в аккаунт Hugging Face (один раз):

   ```powershell
   hf auth login
   ```

2. Упаковать данные, указав репозиторий для карточки датасета:

   ```powershell
   shardkeep pack "D:\work\project\data" "E:\backup\dataset" --hf-repo user/project-data --title "Данные проекта" --lang ru
   ```

3. Загрузить (приватный датасет создается автоматически):

   ```powershell
   shardkeep upload "E:\backup\dataset" --hf user/project-data
   ```

   Если загрузка прервалась, та же команда продолжит ее: уже загруженные файлы пропускаются.

4. Проверить все перед удалением исходных данных:

   ```powershell
   shardkeep check "E:\backup\dataset" --hf user/project-data
   ```

   Команда проверяет содержимое каждой части по манифесту, сверяет каждую исходную папку (она запоминается при упаковке) с архивами и сверяет загруженные файлы по SHA-256. Итог пишется в `check_report.txt`.

### Восстановить

С установленным shardkeep:

```powershell
hf download user/project-data --repo-type dataset --local-dir "D:\restore\backup"
```

```powershell
shardkeep unpack "D:\restore\backup" "D:\restore\data"
```

Без shardkeep, только Python и zstandard:

```powershell
pip install zstandard huggingface_hub
```

```powershell
python "D:\restore\backup\pack_shards.py" verify "D:\restore\backup"
```

```powershell
python "D:\restore\backup\pack_shards.py" unpack "D:\restore\backup" "D:\restore\data"
```

Один набор: `--name <набор>`. Отдельные файлы: `--pattern "scenes/scene_001/*"`. Скачать один набор без остальных: `hf download ... --include "data/<набор>/*" --include "manifest/<набор>/*" --include pack_shards.py`. Без Python часть распаковывается так: `zstd -d -c <часть>.tar.zst | tar -x`.

### Облако через rclone

Хранилище настраивается один раз командой `rclone config` (например, с именем `yadisk` для Яндекс Диска):

```powershell
shardkeep upload "E:\backup\dataset" --rclone yadisk:backup/dataset
```

```powershell
shardkeep check "E:\backup\dataset" --rclone yadisk:backup/dataset
```

SHA-256 сверяется там, где хранилище его отдает (Яндекс Диск, Google Drive). Для остальных файлов сверяется размер, и программа сообщает, сколько файлов проверено только по размеру.

### Проверить zip-архив перед удалением распакованной папки

```powershell
shardkeep compare-zip "D:\work\old_results.zip" "D:\work\old_results" --crc --test
```

`--crc` сравнивает контрольные суммы CRC32, которые хранятся в zip, поэтому архив распаковывать не нужно. `--test` дополнительно проверяет целостность архива.

## Профили сжатия

| Профиль | Что делает |
|---|---|
| `auto` (по умолчанию) | для каждого расширения сжимает выборку файлов. Хорошо сжимаемые файлы – zstd 19, уже сжатые (уменьшаются меньше чем на 10 %) – zstd 1 в отдельных частях |
| `media` | то же, но решение принимается по расширению без чтения файлов: фото, видео, архивы и документы Office – zstd 1 |
| `max` | zstd 22 для всех файлов. Медленно, на уже сжатых данных тратит часы впустую |
| `normal` | zstd 19 для всех файлов, как в исходном `pack_shards.py` |
| `fast` | zstd 3 без режима длинных совпадений |

`--level` задает уровень для хорошо сжимаемых файлов в любом профиле, например `--profile auto --level 22`. Режим длинных совпадений (окно 128 МБ) включен везде, кроме `fast` и частей с уже сжатыми файлами. Части с таким окном распаковывает любая программа zstd без дополнительных параметров.

**Память.** При уровне 19–22 с режимом длинных совпадений каждый поток zstd занимает 1–2 ГБ памяти. Число потоков подбирается автоматически по свободной памяти. Явно заданное `--threads` соблюдается, но при нехватке памяти программа предупреждает.

**Продолжение упаковки.** Повторный запуск той же команды `pack` продолжает упаковку по сохраненному плану: готовые части пропускаются. Параметры, которые не указаны, берутся из сохраненных. Если при продолжении указать другой уровень, программа предупредит, а уровень каждой части запишется рядом с ее манифестом.

## Карточка датасета

`pack` создает `README.md` в папке с архивами, только если его еще нет. Карточку можно редактировать вручную. Команда `shardkeep card` обновляет в ней только таблицу наборов и команды восстановления: они стоят между метками `<!-- shardkeep:begin sets -->` и `<!-- shardkeep:end sets -->` (и `restore`). Карточку без меток команда не меняет. `--force` перезаписывает ее по шаблону, а старая сохраняется в `README.md.bak`.

Лицензия и метаданные:

```powershell
shardkeep card "E:\backup\dataset" --license other --license-name my-license --license-link https://example.org/terms --license-file "D:\work\license.txt" --tag robotics
```

Текст лицензии берется из файла как есть. Пример для данных Waymo Open Dataset: [examples/waymo-license.ru.md](examples/waymo-license.ru.md). Свой шаблон карточки задается параметром `--template`: в нем доступны поля `{{title}}`, `{{description}}`, `{{yaml}}`, `{{sets}}`, `{{restore}}`, `{{license_section}}`, `{{hf_repo}}`, `{{github_url}}`. Параметры запоминаются в `card_settings.json`. Рядом создается `GITHUB_README_SNIPPET.md` – фрагмент для README репозитория с кодом.

## Правила анализатора

Категории файлов и правила отнесения к ним описаны в [src/shardkeep/analyze/rules.toml](src/shardkeep/analyze/rules.toml). Свой файл правил проверяется раньше встроенного:

```toml
[[category]]
id = "annotations"
title = "Annotations"
data = true
advice = "Keep them together with the images."

[[rule]]
category = "annotations"
ext = [".txt"]
dir = ["labels"]

[[notice]]
path = ["*waymo*"]
text = "The project contains Waymo Open Dataset data: it may be shared only with registered users."
```

```powershell
shardkeep analyze "D:\work\project" --rules "D:\work\my_rules.toml"
```

Правило срабатывает, если выполнены все его условия: `ext` (расширения), `not_ext`, `name` (шаблон имени файла), `path` (шаблон пути), `dir` и `not_dir` (шаблон имени любой родительской папки), `min_size` и `max_size` (например `"50MB"`). Правила `[[notice]]` добавляют в отчет предупреждение, если найден подходящий путь.

## JPEG XL

С параметром `--jxl` файлы JPEG переводятся в JPEG XL без потерь (`cjxl --lossless_jpeg=1`). Обычно файл уменьшается примерно на 20 %, а исходный JPEG восстанавливается байт в байт. Каждый файл проверяется сразу при упаковке. Если перевод не удался или файл не восстановился побайтно, в архив кладется исходный JPEG.

```powershell
shardkeep pack "D:\work\photos" "E:\backup\photos" --jxl
```

Для распаковки нужна программа `djxl`. Без нее `unpack --keep-jxl` извлекает файлы `.jxl` как есть.

## Формат архивов

```
E:\backup\dataset\
  README.md                          карточка датасета
  pack_shards.py                     скрипт восстановления
  data\<набор>\<набор>-00000.tar.zst части
  manifest\<набор>\<набор>-00000.jsonl       манифест части
  manifest\<набор>\<набор>-00000.meta.json   параметры части
  manifest\<набор>\plan.jsonl.gz, pack_settings.json, summary.json
```

Полное описание: [docs/format.md](docs/format.md).

**Совместимость с исходным `pack_shards.py`.** shardkeep проверяет, распаковывает и продолжает упаковку архивов, созданных исходным скриптом. Исходный скрипт проверяет и распаковывает архивы shardkeep, кроме наборов, упакованных с `--jxl`. Команды из уже опубликованных карточек (`python pack_shards.py verify ...`) работают с новым скриптом восстановления.

## Особенности Windows

- Пути длиннее 260 символов поддерживаются при упаковке, проверке и распаковке.
- Файлы правил, лицензий и шаблонов читаются в UTF-8, UTF-8 с BOM и UTF-16. Поэтому файлы, созданные перенаправлением `>` в PowerShell 5.1 (UTF-16) или командой `Set-Content -Encoding utf8` (с BOM), читаются без ошибок. Сама программа пишет файлы в UTF-8 без BOM. Исключение составляют таблицы CSV анализатора: в них BOM есть, чтобы Excel открывал их в правильной кодировке. Для Excel с запятой в качестве десятичного разделителя есть параметр `--csv-delimiter ";"`.
- Анализатор проверяет git-репозитории и в папках другого владельца (обходит отказ git с сообщением «dubious ownership»).
- Карточку, сохраненную в Блокноте с переводами строк CRLF, `card` обновляет без изменения переводов строк.

## Ограничения

- Сохраняются только обычные файлы. Символические ссылки и точки соединения пропускаются, пустые папки не сохраняются.
- Время изменения сохраняется с точностью до секунды. Права доступа, владелец и атрибуты не сохраняются, у распакованных файлов права `0644`.
- План упаковки составляется при первом запуске. Файлы, появившиеся позже, в начатый набор не попадают. Их находит `verify --src` или `check`, и для них нужен новый набор.
- Файл, который не удалось прочитать при упаковке (нет доступа, занят другой программой), в архив не попадает и записывается в параметры части. Проверка считает это ошибкой, пока не указан `--allow-skipped`.
- Если файл меняется во время упаковки, в архив попадает его содержимое на момент чтения. `verify --src` сообщит, что файл изменился.
- Сжатие xz работает в один поток и в несколько раз медленнее zstd. Оно используется, только если zstd недоступен или выбран явно.
- Сверка через rclone проверяет SHA-256 только там, где хранилище его отдает.
- Наборы с JPEG XL нельзя распаковать исходным `pack_shards.py`, а для восстановления JPEG нужна программа `djxl`.

pip install -e ".[dev,hf]"
